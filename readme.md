# IoT Event Analysis and Decision Support System

This project implements a deterministic data processing pipeline and
exploratory data analysis (EDA) workflow for analyzing temporal patterns
of critical events in IoT-based monitoring systems.

The system is designed to support research on human-in-the-loop response
behavior, focusing on event dynamics, response time, and
decision-support modeling.

------------------------------------------------------------------------

## Objective

To extract, process, and analyze temporal event data generated by an IoT
system, enabling:

-   Understanding of operator response behavior
-   Identification of temporal patterns in critical events
-   Support for association rule mining and decision-making models

------------------------------------------------------------------------

## System Overview

The project is structured into three main components:

-   **Deterministic Pipeline** → Data cleaning and feature engineering\
-   **EDA Module** → Visualization and exploratory analysis\
-   **Rules Pipeline** → Association rule generation (Apriori-based and others)

------------------------------------------------------------------------

## Pipeline Design

The deterministic pipeline follows a structured and reproducible
workflow:

1.  Data loading\
2.  Datetime parsing\
3.  Data cleaning\
4.  Temporal feature engineering\
5.  Event dynamics modeling\
6.  Rolling window feature generation\
7.  Final dataset structuring

### Key Features Generated

-   Response time (`response_seconds`)
-   Time between events (`time_since_prev_alert_s`)
-   Alerts per time window (`alerts_last_15m`, `alerts_last_60m`)
-   Temporal context:
    -   Hour of day
    -   Day of week
    -   Part of day
    -   Weekend indicator

------------------------------------------------------------------------

## Exploratory Data Analysis (EDA)

The project includes visualization tools for:

-   Response time distribution (Histogram + KDE)
-   Response time dispersion (Boxplot)
-   Response rate by hour
-   Weekday vs weekend comparison
-   Correlation matrix between variables

------------------------------------------------------------------------

## Methodological Considerations

-   Deterministic pipeline ensures reproducibility
-   Temporal ordering is preserved for consistency
-   No data leakage:
    -   `served_time` is not used as an explanatory feature
-   Designed for interpretability and downstream rule extraction

## How to Run

### 1. Configure paths

Edit `config.py`:

``` python
OBSERVATIONAL_DATASET_PATH = "path/to/0_observational_dataset.csv"
OBSERVATIONAL_CLEANED_PREPROCESSED_DATASET_PATH = "path/to/1_observational_cleaned_preprocessed_dataset.csv"

SYNTHETIC_EXPANDED_DATASET_PATH = "path/to/2_synthetic_expanded_dataset.csv"
SYNTHETIC_DATASET_ONLY_PATH = "path/to/2_synthetic_records_only.csv"
SYNTHETIC_EXPANSION_VALIDATION_REPORT = "path/to/2_synthetic_expansion_validation_report.csv"

OBSERVATIONAL_FEATURE_ENGINEERING_DATASET_PATH = "path/to/3_observational_feature_engineering_dataset.csv"
SYNTETIC_FEATURE_ENGINEERING_DATASET_PATH = "path/to/3_synthetic_feature_engineering_dataset.csv"

OBSERVATIONAL_DISCRETIZATION_CATEGORICAL_DATASET_PATH = "path/to/4_observational_discretization_categorical_dataset.csv"
SYNTETIC_DISCRETIZATION_CATEGORICAL_DATASET_PATH = "path/to/4_synthetic_discretization_categorical_dataset.csv"

OBSERVATIONAL_TRANSACTIONAL_DATASET_PATH = "path/to/5_observational_transactional_dataset.csv"
SYNTETIC_TRANSACTIONAL_DATASET_PATH = "path/to/5_synthetic_transactional_dataset.csv"
```

------------------------------------------------------------------------

### 2. Execute pipeline or analysis

In `main.py`, select the desired step:

``` python
step = "cleaning_preproccess_pipeline"
```
------------------------------------------------------------------------

### 3. Run

``` bash
python main.py
```
